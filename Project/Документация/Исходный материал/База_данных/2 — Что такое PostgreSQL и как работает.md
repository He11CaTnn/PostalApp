ЧТО ТАКОЕ POSTGRESQL И КАК ОНА РАБОТАЕТ
=========================================

Что это
--------
PostgreSQL — объектно-реляционная система управления базами данных (СУБД)
с открытым исходным кодом. «Реляционная» означает, что данные хранятся
в таблицах со строками и столбцами, а между таблицами существуют явные
связи. «Объектная» часть — возможность создавать собственные типы данных,
функции и операторы прямо внутри базы.

PostgreSQL не является приложением с интерфейсом — это серверный процесс
(демон postgres), который принимает соединения от клиентов, выполняет
запросы и возвращает результаты. Клиентом может быть консоль psql,
графический инструмент (DBeaver, pgAdmin) или программный драйвер
в коде приложения.

Как хранятся данные
--------------------
Данные хранятся в файлах на диске в специальном формате — в так называемом
кластере баз данных (data directory). Один сервер PostgreSQL может содержать
несколько независимых баз данных; в этом проекте используется одна база
с именем pochta_db.

Внутри базы данные организованы в страницы фиксированного размера (8 КБ).
Каждая страница содержит несколько строк таблицы. PostgreSQL никогда не
перезаписывает строку при обновлении — вместо этого старая версия помечается
как устаревшая, а рядом записывается новая. Это механизм MVCC (Multi-Version
Concurrency Control): разные транзакции видят согласованный снимок данных
без блокировки друг друга.

Транзакции и ACID
------------------
Любая операция в PostgreSQL происходит внутри транзакции. Транзакция — это
атомарная единица работы: либо выполняются все её шаги, либо не выполняется
ни один. PostgreSQL полностью соответствует свойствам ACID:

  Atomicity     — транзакция либо завершается целиком, либо откатывается.
  Consistency   — база остаётся в корректном состоянии до и после.
  Isolation     — транзакции не мешают друг другу (MVCC).
  Durability    — подтверждённые данные сохраняются даже при сбое сервера.
                  Это обеспечивает WAL — журнал упреждающей записи,
                  в который изменения пишутся раньше чем применяются к файлам.

Типы данных
-----------
PostgreSQL поддерживает широкий набор типов: числа (integer, real, double
precision), строки (varchar, text), даты и время (timestamp with time zone),
булевы значения, массивы, JSON и UUID.

В этом проекте:
  UUID — первичные ключи всех таблиц, генерируются функцией uuid_generate_v4()
         из расширения uuid-ossp. UUID гарантирует глобальную уникальность
         идентификатора без координации между клиентами.
  text — неограниченные строки (пароли, тексты заданий, списки ID через запятую).
  varchar(N) — строки с ограничением длины (имена, адреса, роли).
  double precision — координаты (широта, долгота) с высокой точностью.
  timestamp with time zone — даты с часовым поясом (UTC на сервере).
  boolean — флаг постоянного доступа устройства.

Индексы
--------
Индекс — вспомогательная структура данных (обычно B-дерево), которая
ускоряет поиск строк по конкретному столбцу. Без индекса PostgreSQL
сканирует всю таблицу последовательно (sequential scan).

В этом проекте созданы четыре индекса:
  idx_metki_id_uchastka     — Метки.Id участка
  idx_uzly_id_uchastka      — Узлы.Id участка
  idx_sotrudniki_id_logina  — Сотрудники.Id логина
  idx_zadaniya_id_sotr      — Задания.Id сотрудника

Все четыре — по полям внешних ключей, по которым чаще всего происходит
JOIN или фильтрация.

Внешние ключи и каскадное удаление
------------------------------------
Внешний ключ (FOREIGN KEY) — ограничение, которое запрещает создать строку
со ссылкой на несуществующую запись и, в зависимости от настройки,
управляет удалением связанных данных.

В этой базе все внешние ключи настроены с ON DELETE CASCADE:
  удалить Участок → автоматически удалятся все его Метки и Узлы.
  удалить Логин → автоматически удалится запись Сотрудника.
  удалить Сотрудника → автоматически удалятся все его Задания.

Пользователь и права
---------------------
Все таблицы принадлежат пользователю pochta_admin — это не системный
администратор PostgreSQL (superuser), а прикладной пользователь с правами
только на свою базу. Приложения подключаются именно под ним.
Пароль хранится в config.json и никогда не попадает в код.
