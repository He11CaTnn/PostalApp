КАК БАЗА ДАННЫХ ВЗАИМОДЕЙСТВУЕТ С ПРИЛОЖЕНИЯМИ
================================================

Три точки входа в базу
-----------------------
К базе данных обращаются три независимых компонента системы.
Все три используют одного и того же пользователя pochta_admin
и те же параметры подключения из config.json.

──────────────────────────────────────────────────────────────────
1. FastAPI-сервер (main.py) — Python, asyncpg
──────────────────────────────────────────────────────────────────
Библиотека: asyncpg — асинхронный драйвер PostgreSQL для Python.
Соединение открывается на каждый запрос и закрывается сразу после него.
Пула соединений нет — каждый вызов asyncpg.connect() создаёт новое TCP-соединение.

Что делает:
  /api/getconfig и /api/getconfig_extra:
    SELECT "Пароль" FROM "Логин" WHERE "Почта" = $1
    Проверяет PBKDF2-SHA256 хэш на стороне Python.
    При совпадении возвращает клиенту строку подключения к PostgreSQL напрямую.

  /api/checkdevice:
    SELECT id FROM "Устройства"
    WHERE "Id материнской платы" = $1 AND "Постоянный доступ" = true
    Ищет устройство с разрешённым автовходом.

Параметры подключения берутся из config.json → поле "conn" (ip|port|db|user|password).
DSN строится функцией build_dsn() как postgresql://user:password@host:port/database.

──────────────────────────────────────────────────────────────────
2. PostalApp (C#, Npgsql / собственная ORM PgQuery)
──────────────────────────────────────────────────────────────────
Библиотека: Npgsql — официальный .NET-драйвер PostgreSQL.
Параметры подключения PostalApp получает от FastAPI-сервера при входе —
сервер возвращает строку config ("ip|port|db|user|password") в ответе JSON.
Приложение само разбирает её и хранит в Program.ServerIP, ServerPort и т.д.

Строка подключения формируется как:
  Host=...; Port=...; Database=...; Username=...; Password=...;
  Encoding=UTF8; Client Encoding=UTF8;

Обращение к БД происходит через PgClient.From<T>(), который строит
параметризованные SQL-запросы автоматически на основе атрибутов [DbTable]/[DbColumn].

Таблицы с которыми работает PostalApp:
  Логин       — проверка пароля при ручном входе (двойная верификация).
  Сотрудники  — загрузка профиля, смена роли, добавление новых сотрудников.
  Устройства  — регистрация/обновление устройства, автовход по материнской плате.
  Участки     — загрузка на карту, создание, удаление.
  Узлы        — вершины полигонов участков.
  Метки       — адресные точки, добавление, редактирование, перемещение.
  Читатели    — список получателей, управление.
  Подписки    — оформление и просмотр подписок.
  Издания     — каталог изданий.
  Задания     — создание, смена статуса.
  тест        — проверка живости соединения при запуске.

Характер обращений: смешанный. Директор читает все таблицы полностью.
Почтальон и оператор работают только с записями своих участков.
Фильтрация по участку происходит на клиенте через WHERE "Id участка" IN (список).

──────────────────────────────────────────────────────────────────
3. PostalApp-Extra (C#, Npgsql через прямую строку подключения)
──────────────────────────────────────────────────────────────────
Аналогично PostalApp — получает строку подключения от /api/getconfig_extra.
Отличие: программа использует PostgreSQL только для переноса данных, а не
для ежедневной работы. Основное хранилище Extra — локальная БД Access (BD.accdb).

Операции с PostgreSQL:
  Перенос Access → PostgreSQL:
    DELETE FROM "Узлы", DELETE FROM "Участки", DELETE FROM "Метки".
    INSERT/UPSERT в "Участки", "Узлы", "Метки" пакетами.
    Управление внешними ключами: DROP CONSTRAINT → вставка → ADD CONSTRAINT.

  Перенос PostgreSQL → Access:
    SELECT из "Участки", "Узлы", "Метки".
    INSERT в локальные таблицы Access.

  Перенос PostgreSQL → карта:
    SELECT из "Участки", "Узлы", "Метки" для отображения на GMap.NET.

PostgreSQL-транзакции при переносе не используются явно — операции идут
последовательно; при сбое на середине данные могут оказаться частично перенесены.

──────────────────────────────────────────────────────────────────
МАРШРУТ ДАННЫХ ПРИ ВХОДЕ ПОЛЬЗОВАТЕЛЯ
──────────────────────────────────────────────────────────────────
1. Пользователь вводит email + пароль в PostalApp.
2. PostalApp → HTTPS → FastAPI → asyncpg → PostgreSQL:
   SELECT "Пароль" FROM "Логин" WHERE "Почта" = '...'
3. FastAPI проверяет PBKDF2, возвращает {"config": "ip|port|db|user|password"}.
4. PostalApp разбирает config и устанавливает прямое TCP-соединение с PostgreSQL
   через Npgsql.
5. PostalApp повторно проверяет пароль через свою реализацию PBKDF2 (двойная
   верификация: на сервере и на клиенте).
6. Загружаются данные сотрудника, его участки, затем открывается основная форма.

После этого FastAPI-сервер из цепочки выбывает — всё дальнейшее взаимодействие
происходит напрямую между PostalApp и PostgreSQL без посредников.
