ШАГ 1.5 — SYSTEMD-СЕРВИС ДЛЯ FASTAPI
======================================

Что делает сервис
-----------------
Запускает uvicorn с FastAPI-приложением как фоновый процесс.
Автоматически перезапускается при сбое.
Стартует вместе с системой при перезагрузке сервера.

Создать файл сервиса
---------------------
  nano /etc/systemd/system/postalapp-api.service

Вставить следующее содержимое.
Замени {ПАПКА_API} на путь к папке API:

──────────────────────────────────────────────────────────
[Unit]
Description=PostalApp Config API
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory={ПАПКА_API}
ExecStart={ПАПКА_API}/venv/bin/uvicorn main:app --host 127.0.0.1 --port 8765
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
──────────────────────────────────────────────────────────

Сохранить: Ctrl+O, Enter, Ctrl+X.

Параметры сервиса:
  --host 127.0.0.1  — uvicorn слушает только локально (Nginx проксирует снаружи)
  --port 8765       — порт uvicorn (должен совпадать с proxy_pass в nginx-конфиге)
  Restart=always    — перезапуск при любом сбое
  RestartSec=5      — пауза 5 секунд перед перезапуском

Примечание по After=
  В исходном сервисе было After=network.target postgresql.service.
  Если PostgreSQL установлен на том же сервере — верни postgresql.service.
  Если PostgreSQL на отдельном сервере — достаточно network.target.

Запустить и активировать сервис
---------------------------------
  systemctl daemon-reload
  systemctl enable postalapp-api
  systemctl start postalapp-api

Проверить статус:
  systemctl status postalapp-api

Ожидаемый вывод:
  Active: active (running)
  Строки с "Uvicorn running on http://127.0.0.1:8765"

Проверить логи сервиса:
  journalctl -u postalapp-api -n 50

Если сервис не запустился — смотри последние строки журнала для диагностики ошибки.

Управление сервисом
--------------------
  systemctl start postalapp-api    — запустить
  systemctl stop postalapp-api     — остановить
  systemctl restart postalapp-api  — перезапустить
  systemctl status postalapp-api   — статус

После изменения main.py или config.json — обязательно перезапустить:
  systemctl restart postalapp-api

Полная проверка стека
----------------------
После запуска сервиса проверить что весь стек работает:

1. Сервис запущен:
   systemctl is-active postalapp-api
   → Ответ: active

2. uvicorn слушает порт:
   ss -tulpn | grep 8765
   → Строка с 127.0.0.1:8765

3. Nginx проксирует корректно (с сервера):
   curl -sk https://{IP_СЕРВЕРА}/api/getconfig -X POST \
     -H "Content-Type: application/json" \
     -d '{"login":"test","password":"test","version":"0.1.22","exe_md5":"abc"}'
   → Ответ JSON: {"detail":"Update required"} или {"detail":"Integrity check failed"}
   Главное — ответ получен, стек работает.
