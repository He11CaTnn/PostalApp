ШАГ 1.4 — NGINX: КОНФИГ API И РАЗДАЧА ОБНОВЛЕНИЙ
==================================================

Как работает Nginx в этой системе
-----------------------------------
Nginx выполняет две роли одновременно:
  1. HTTPS (порт 443) — принимает запросы от приложений к /api/ и
     проксирует их на uvicorn (127.0.0.1:8765, только локально).
  2. HTTP (порт 80) — отдаёт файлы обновлений (update.zip, манифесты)
     клиентам PostalApp.

Создать конфигурационный файл
------------------------------
Запомни имя файла конфига как {ИМЯ_КОНФИГА_API} (например: pochta).

  nano /etc/nginx/sites-available/{ИМЯ_КОНФИГА_API}

Вставить следующее содержимое.
Замени {IP_СЕРВЕРА} на IP, {ПАПКА_CERT} на путь к папке сертификата,
{ПАПКА_ОБНОВЛЕНИЙ} на путь к папке обновлений:

──────────────────────────────────────────────────────────
# HTTPS — API для получения конфигурации
server {
    listen 443 ssl;
    server_name {IP_СЕРВЕРА};

    ssl_certificate     {ПАПКА_CERT}/server.crt;
    ssl_certificate_key {ПАПКА_CERT}/server.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    location /api/ {
        # Preflight — браузер спрашивает разрешение перед cross-origin запросом
        if ($request_method = OPTIONS) {
            add_header Access-Control-Allow-Origin  *;
            add_header Access-Control-Allow-Methods "POST, OPTIONS";
            add_header Access-Control-Allow-Headers "Content-Type";
            add_header Content-Length 0;
            add_header Content-Type  text/plain;
            return 204;
        }

        add_header Access-Control-Allow-Origin *;

        proxy_pass         http://127.0.0.1:8765;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
    }
}

# HTTP — раздача обновлений (update.zip, манифесты)
server {
    listen 80;
    server_name {IP_СЕРВЕРА};
    autoindex off;

    location /updates/ {
        alias {ПАПКА_ОБНОВЛЕНИЙ}/;
        try_files $uri =404;

        # Отключаем кэш manifest.json чтобы клиент всегда
        # получал актуальную версию
        location /updates/manifest.json {
            alias {ПАПКА_ОБНОВЛЕНИЙ}/manifest.json;
            add_header Cache-Control "no-cache, no-store";
            add_header Access-Control-Allow-Origin *;
        }
    }
}
──────────────────────────────────────────────────────────

Сохранить файл: Ctrl+O, Enter, Ctrl+X.

Активировать конфиг
--------------------
  ln -s /etc/nginx/sites-available/{ИМЯ_КОНФИГА_API} /etc/nginx/sites-enabled/

Отключить дефолтный конфиг (если он активен и мешает):
  rm -f /etc/nginx/sites-enabled/default

Проверить синтаксис и перезапустить Nginx:
  nginx -t
  systemctl reload nginx

Проверить что Nginx слушает нужные порты:
  ss -tulpn | grep nginx

Должны быть строки с портами: 80, 443.

Проверить API вручную (с сервера)
-----------------------------------
  curl -k https://127.0.0.1/api/getconfig

Ожидаемый ответ: {"detail":"..."} — любой JSON-ответ, главное что
соединение установилось. Флаг -k игнорирует проверку сертификата.

Примечание по proxy_pass
--------------------------
uvicorn слушает на 127.0.0.1:8765 — только локально.
Снаружи порт 8765 недоступен — все запросы идут через Nginx.
Менять порт 8765 нужно одновременно в двух местах:
  - systemd-сервисе (ExecStart ... --port 8765)
  - этом nginx-конфиге (proxy_pass http://127.0.0.1:8765)
