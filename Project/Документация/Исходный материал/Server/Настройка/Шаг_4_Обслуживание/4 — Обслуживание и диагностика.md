ШАГ 4 — ОБСЛУЖИВАНИЕ СЕРВЕРА
==============================

Ежедневная рутина
-----------------
В нормальном режиме работы сервер не требует вмешательства.
Все три компонента (API, Nginx, PostgreSQL) управляются systemd и
перезапускаются автоматически при сбое.

Проверить что всё живо (занимает 30 секунд):
  systemctl is-active postalapp-api nginx postgresql
  → каждая строка должна вернуть: active

Если какой-то сервис вернул inactive или failed — см. раздел «Диагностика» ниже.

Работа с обновлениями PostalApp
---------------------------------
После каждого нового релиза через WinSCP загружаешь файлы в {ПАПКА_ОБНОВЛЕНИЙ}:
  versions/vX.Y.Z/update.zip
  versions/vX.Y.Z/version_manifest.json
  versions/vX.Y.Z/PostalApp_Setup_vX.Y.Z.exe  (если нужен)
  manifest.json  (глобальный, в корень {ПАПКА_ОБНОВЛЕНИЙ})

Nginx отдаёт эти файлы статически — перезапускать ничего не нужно.
Сразу после загрузки клиенты получат новую версию.

Работа с сайтом (обновление файлов)
--------------------------------------
Через WinSCP заменяешь файлы в {ПАПКА_САЙТА}/.
Перезапуск Nginx не нужен — файлы отдаются сразу.
Исключение: если менял Nginx-конфиг — делай nginx -t && systemctl reload nginx.

Изменение config.json (API)
-----------------------------
Через WinSCP открываешь {ПАПКА_API}/config.json, редактируешь, сохраняешь.
После сохранения обязательно перезапустить API:
  systemctl restart postalapp-api

main.py изменяется аналогично — тоже требует перезапуска сервиса.

Перезагрузка сервера
----------------------
После любого обновления ОС (apt upgrade) с заменой ядра требуется reboot:
  reboot

После перезагрузки всё поднимется автоматически — Nginx и postalapp-api
настроены на автозапуск (systemctl enable).

Проверка SSL-сертификата Let's Encrypt (для сайта)
----------------------------------------------------
Certbot обновляет сертификат автоматически. Посмотреть дату истечения:
  certbot certificates
  → Строка "Expiry Date: ..."

Принудительное обновление (если вдруг нужно):
  certbot renew

Проверить что автообновление работает:
  systemctl status certbot.timer
  → Active: active

Самоподписной сертификат API (срок 10 лет)
-------------------------------------------
Истекает через 10 лет. Когда истечёт — нужно:
  1. Пересоздать сертификат (см. Шаг 1.3)
  2. Получить новый fingerprint
  3. Вставить fingerprint в SecureConfig.cs (PostalApp) и LoginForm.cs (PostalApp-Extra)
  4. Пересобрать оба приложения и выпустить новые версии

Просмотр логов
--------------
Логи API-сервиса (последние 100 строк):
  journalctl -u postalapp-api -n 100

Следить за логами в реальном времени:
  journalctl -u postalapp-api -f
  (выход: Ctrl+C)

Логи Nginx (ошибки):
  tail -100 /var/log/nginx/error.log

Логи Nginx (доступ):
  tail -100 /var/log/nginx/access.log

ПРОБЛЕМА: API не отвечает (приложение не может войти)
-------------------------------------------------------
1. Проверить сервис:
   systemctl status postalapp-api
   Если failed → смотреть почему:
   journalctl -u postalapp-api -n 50

2. Частые причины:
   a) Синтаксическая ошибка в main.py после правки:
      → journalctl покажет Traceback; исправить файл; systemctl restart postalapp-api
   b) Ошибка в config.json (неверный JSON):
      → python3 -c "import json; json.load(open('{ПАПКА_API}/config.json'))"
        Если ошибка — исправить config.json
   c) Порт 8765 занят другим процессом:
      → ss -tulpn | grep 8765
        Убить мешающий процесс: kill -9 {PID}; systemctl restart postalapp-api

3. Убедиться что Nginx проксирует:
   curl -sk https://{IP_СЕРВЕРА}/api/getconfig -X POST \
     -H "Content-Type: application/json" \
     -d '{"login":"x","password":"x","version":"0.0.0","exe_md5":"x"}'
   → Любой JSON-ответ означает что стек работает.

ПРОБЛЕМА: Nginx не запускается / reload fails
-----------------------------------------------
  nginx -t
  → Покажет конкретную строку с ошибкой в конфиге.
  Исправить указанный файл; повторить nginx -t; systemctl reload nginx.

ПРОБЛЕМА: Сайт не открывается
-------------------------------
1. Проверить Nginx:
   systemctl status nginx
   nginx -t

2. Если ошибка SSL-сертификата:
   certbot certificates
   Если истёк → certbot renew; systemctl reload nginx

3. Если порт 443/80 не слушается:
   ss -tulpn | grep nginx
   → Если пусто: systemctl start nginx

4. Если файрвол блокирует:
   ufw status
   → Убедиться что порты 80 и 443 открыты

ПРОБЛЕМА: Ошибка 403 Forbidden в приложении
--------------------------------------------
MD5 exe-файла не совпадает с эталонным в version_manifest.json.
Причины:
  a) Был выпущен новый установщик но manifests.py не запускался →
     запусти manifests.py, загрузи новый version_manifest.json на сервер.
  b) Файл на сервере повреждён при загрузке →
     перезалей version_manifest.json через WinSCP.

ПРОБЛЕМА: Ошибка 426 в приложении (Update required)
-----------------------------------------------------
Версия приложения отсутствует в versions[] глобального manifest.json.
Причины:
  a) Забыли обновить manifest.json после релиза →
     запусти manifests.py или вручную добавь версию в manifest.json.
  b) Намеренно убрана поддержка старой версии — всё правильно.

ПРОБЛЕМА: Rate limit (ошибка 429) у всех пользователей с одного офиса
-----------------------------------------------------------------------
Если несколько сотрудников работают за NAT (один внешний IP) и один
из них много раз неверно вводит пароль — все получат блокировку на 60 секунд.
Лимиты в памяти процесса — сбрасываются при перезапуске API:
  systemctl restart postalapp-api
  (ТОЛЬКО в исключительных ситуациях — это сбросит все легитимные лимиты тоже)

ПРОБЛЕМА: Авторизация через Google не работает на сайте
---------------------------------------------------------
1. Проверить что домен добавлен в Firebase:
   Firebase Console → Authentication → Settings → Authorized domains
   Должны быть: postalapp.ru, www.postalapp.ru

2. Проверить корректность firebase.apiKey и других полей в config.js.

3. Проверить HTTPS — Google OAuth работает только по HTTPS (не HTTP).

ПРОБЛЕМА: Обновление установщика PostalApp-Extra не подхватывается сайтом
---------------------------------------------------------------------------
После загрузки нового .exe в {ПАПКА_САЙТА}/assets/postalapp-extra/versions/
нужно обновить manifest.json в {ПАПКА_САЙТА}/assets/postalapp-extra/:
  {"versions": ["новая_версия", "старая_версия"]}
Первый элемент — самая новая. Сайт строит ссылку скачивания по нему.

ПОЛЕЗНЫЕ КОМАНДЫ НА КАЖДЫЙ ДЕНЬ
──────────────────────────────────────────────────────────────────

Перезапустить всё сразу:
  systemctl restart postalapp-api nginx

Место на диске (не допускать заполнения):
  df -h
  du -sh /var/www/*

Очистить старые apt-пакеты:
  apt autoremove -y && apt autoclean

Обновить пакеты ОС:
  apt update && apt upgrade -y
  (После обновления ядра — reboot)

Список активных сервисов:
  systemctl list-units --state=running --type=service

Последние входы на сервер (подозрительная активность):
  last -n 20

Заблокированные IP в auth.log (brute-force попытки):
  grep "Failed password" /var/log/auth.log | tail -20
