ШАГ 3 — НАСТРОЙКА САЙТА: ОБЗОР И ВАРИАНТ А
===========================================

Три варианта развёртывания
---------------------------
Каждый следующий вариант строится поверх предыдущего — не нужно начинать заново.

  ВАРИАНТ А — Без домена, HTTP + IP:8080
    Самый быстрый запуск. Сайт доступен по http://{IP_СЕРВЕРА}:8080.
    Firebase Authentication может не работать по голому IP в ряде браузеров.
    Подходит для первичной проверки работоспособности.

  ВАРИАНТ Б — Домен + HTTPS, не виден в поиске
    Требует куплённый домен.
    Сайт доступен по https://example.ru с зелёным замком.
    Поисковики не индексируют (noindex).
    Идеален для корпоративного/внутреннего использования.

  ВАРИАНТ В — Домен + HTTPS, виден в поиске
    Строится поверх Варианта Б — убирается запрет индексации.
    Сайт регистрируется в Google и Яндекс.

───────────────────────────────────────────────────────────────────────────
ВАРИАНТ А — HTTP + IP:8080
───────────────────────────────────────────────────────────────────────────

Загрузить файлы сайта
----------------------
Через WinSCP скопируй все файлы сайта в {ПАПКА_САЙТА}:
  index.html, admin.html, css/, js/, assets/

Структура должна выглядеть так:
  {ПАПКА_САЙТА}/
    index.html
    admin.html
    css/style.css
    js/config.js
    js/app.js
    js/admin.js
    assets/icons/
    assets/postalapp-extra/manifest.json
    assets/postalapp-extra/versions/
    assets/screenshot1.png ...

Создать Nginx-конфиг для сайта
--------------------------------
Запомни имя файла конфига как {ИМЯ_КОНФИГА_САЙТА} (например: postalapp-site).

  nano /etc/nginx/sites-available/{ИМЯ_КОНФИГА_САЙТА}

Вставить содержимое.
Замени {ПАПКА_САЙТА} и {ПАПКА_ОБНОВЛЕНИЙ} на свои пути:

──────────────────────────────────────────────────────────
server {
    listen 8080;
    server_name _;

    root {ПАПКА_САЙТА};
    index index.html;

    location / {
        try_files $uri $uri/ $uri.html =404;
    }

    location /updates/ {
        alias {ПАПКА_ОБНОВЛЕНИЙ}/;
        autoindex off;
    }
}
──────────────────────────────────────────────────────────

Сохранить: Ctrl+O, Enter, Ctrl+X.

Активировать и перезапустить Nginx:
  ln -s /etc/nginx/sites-available/{ИМЯ_КОНФИГА_САЙТА} /etc/nginx/sites-enabled/
  nginx -t
  systemctl reload nginx

Проверка:
  Открой в браузере: http://{IP_СЕРВЕРА}:8080
  Сайт должен загрузиться.

Настроить config.js на сайте
------------------------------
Через WinSCP открой {ПАПКА_САЙТА}/js/config.js.
Заполни поля:
  - firebase.apiKey и другие firebase-параметры (взять из Firebase Console).
  - superAdminEmail — email главного администратора.
  - urls.mainManifest — http://{IP_СЕРВЕРА}/updates/manifest.json
  - urls.mainVersionBase — http://{IP_СЕРВЕРА}/updates/versions/
  - urls.extraManifest — http://{IP_СЕРВЕРА}:8080/assets/postalapp-extra/manifest.json
  - urls.extraVersionBase — http://{IP_СЕРВЕРА}:8080/assets/postalapp-extra/versions/

Сохранить. Обновить страницу в браузере.

Ограничение Варианта А
-----------------------
Firebase Authentication работает только с разрешёнными доменами.
По умолчанию localhost разрешён, но голые IP-адреса могут не работать
в зависимости от провайдера OAuth и браузера.

В Firebase Console → Authentication → Settings → Authorized domains
добавь IP-адрес сервера в список. Если авторизация через Google всё равно
не работает по IP — переходи к Варианту Б (домен + HTTPS).
