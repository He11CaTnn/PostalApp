ШАГ 3 — ВАРИАНТ Б: ДОМЕН + HTTPS + СКРЫТИЕ ОТ ПОИСКА
=======================================================

Строится поверх Варианта А. Сайт доступен по https://postalapp.ru с зелёным замком.
Поисковики не индексируют — только прямая ссылка.

Требования:
  - Куплен и делегирован домен (в примере: postalapp.ru)
  - Вариант А выполнен: файлы сайта загружены в {ПАПКА_САЙТА}
  - Файлы обновлений в {ПАПКА_ОБНОВЛЕНИЙ}

Б.1 — Настроить DNS у регистратора
-------------------------------------
В панели управления DNS создай две A-записи:

  Тип: A | Имя: @   | Значение: {IP_СЕРВЕРА} | TTL: 3600
  Тип: A | Имя: www | Значение: {IP_СЕРВЕРА} | TTL: 3600

DNS обновляется до 24 часов, обычно 15–30 минут.
Проверить что DNS применился:
  ping postalapp.ru
  → должен отвечать {IP_СЕРВЕРА}

Б.2 — Установить Certbot
--------------------------
  apt install -y certbot python3-certbot-nginx

Б.3 — Получить SSL-сертификат от Let's Encrypt
------------------------------------------------
Замени postalapp.ru на свой домен:
  certbot certonly --nginx -d postalapp.ru -d www.postalapp.ru

Certbot задаст вопросы:
  - Email: введи реальный email (получишь уведомления об истечении сертификата)
  - Agree to terms: Y
  - Share email with EFF: по желанию

После успеха сертификат появится в:
  /etc/letsencrypt/live/postalapp.ru/fullchain.pem
  /etc/letsencrypt/live/postalapp.ru/privkey.pem

Сертификат обновляется автоматически каждые 90 дней.
Проверить автообновление:
  certbot renew --dry-run
  → Ответ: "Simulating renewal... SUCCESS"

Б.4 — Обновить Nginx-конфиг для домена
-----------------------------------------
Открой конфиг сайта созданный в Варианте А:
  nano /etc/nginx/sites-available/{ИМЯ_КОНФИГА_САЙТА}

Полностью замени содержимое на следующее.
Замени postalapp.ru на свой домен, {ПАПКА_САЙТА} и {ПАПКА_ОБНОВЛЕНИЙ}:

──────────────────────────────────────────────────────────
# HTTP → редирект на HTTPS
server {
    listen 80;
    server_name postalapp.ru www.postalapp.ru;
    return 301 https://$host$request_uri;
}

# HTTPS — основной сайт
server {
    listen 443 ssl;
    server_name postalapp.ru www.postalapp.ru;

    ssl_certificate     /etc/letsencrypt/live/postalapp.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/postalapp.ru/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    root  {ПАПКА_САЙТА};
    index index.html;

    # Панель администратора: /admin → admin.html (URL в строке не меняется)
    location = /admin {
        try_files /admin.html =404;
    }

    # Обновления и установщики основного приложения
    location /updates/ {
        alias {ПАПКА_ОБНОВЛЕНИЙ}/;
        autoindex off;
    }

    # Всё остальное: файл → директория → index.html (SPA-режим)
    # Нужно чтобы /features, /download, /auth отдавали index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
──────────────────────────────────────────────────────────

Сохранить: Ctrl+O, Enter, Ctrl+X.

Как работает этот конфиг
--------------------------
HTTP (порт 80):
  Любой запрос на http://postalapp.ru → 301 редирект на https://postalapp.ru.

HTTPS (порт 443):
  /admin         → отдаёт admin.html не меняя URL (пользователь видит /admin в строке).
  /updates/...   → файлы из {ПАПКА_ОБНОВЛЕНИЙ}/ (update.zip, манифесты).
  /features, /download, /auth и любой другой путь без файла → index.html.
                 JS в index.html при загрузке читает путь и скроллит к нужной секции.
  Реальные файлы (css/, js/, assets/) → отдаются напрямую.

SPA-пути и скролл
------------------
В index.html вшит JS-скрипт который при открытии /features, /download, /auth
автоматически скроллит страницу к соответствующей секции.
Ссылки на сайте: /features, /download, /auth (а не #features, #download, #auth).
Ссылка на панель администратора: /admin.

Проверить и перезапустить Nginx:
  nginx -t
  systemctl reload nginx

Б.5 — Загрузить обновлённые файлы сайта
-----------------------------------------
Через WinSCP обнови файлы в {ПАПКА_САЙТА}/:
  index.html — содержит noindex/nofollow и SPA-скрипт скролла.
  admin.html — ссылка «На сайт» ведёт на /, добавлен noindex.

Перезапуск Nginx не нужен — HTML-файлы отдаются сразу.

Б.6 — Запрет индексации
-------------------------
В index.html и admin.html уже должны быть мета-теги:
  <meta name="robots" content="noindex, nofollow">

Дополнительно создать robots.txt:
  nano {ПАПКА_САЙТА}/robots.txt

  Содержимое:
    User-agent: *
    Disallow: /

  Сохранить: Ctrl+O, Enter, Ctrl+X.

Б.7 — Обновить URLs в config.js
---------------------------------
Через WinSCP открой {ПАПКА_САЙТА}/js/config.js.
Обнови поля urls:
  urls.mainManifest:     http://{IP_СЕРВЕРА}/updates/manifest.json
    (обновления PostalApp — по HTTP, по IP; API-сертификат отдельный)
  urls.mainVersionBase:  http://{IP_СЕРВЕРА}/updates/versions/
  urls.extraManifest:    https://postalapp.ru/assets/postalapp-extra/manifest.json
  urls.extraVersionBase: https://postalapp.ru/assets/postalapp-extra/versions/
Сохранить.

Б.8 — Добавить домен в Firebase
---------------------------------
Firebase Console → Authentication → Settings → Authorized domains → Add domain:
  Добавить: postalapp.ru
  Добавить: www.postalapp.ru
Без этого Google OAuth отклонит авторизацию с нового домена.

Б.9 — Проверить
-----------------
Открой в браузере:

  https://postalapp.ru              → главная страница, зелёный замок
  https://postalapp.ru/admin        → панель администратора (URL остаётся /admin)
  https://postalapp.ru/features     → главная, автоскролл к секции «Возможности»
  https://postalapp.ru/download     → главная, автоскролл к секции «Скачать»
  http://postalapp.ru               → редирект на https://
  https://www.postalapp.ru          → сайт работает

Примечания
----------
Старый конфиг Варианта А (порт 8080) можно оставить или удалить —
он не конфликтует т.к. у него другой server_name (голый IP).

Конфиг pochta (API на 443 по IP) тоже не трогать — разные server_name
(IP и домен — разные блоки, Nginx различает их).

На сервере теперь три активных Nginx-блока:
  - pochta    → 443 (API по IP), 80 (обновления по IP)
  - сайт      → 443 (сайт по домену), 80 (редирект на HTTPS)
