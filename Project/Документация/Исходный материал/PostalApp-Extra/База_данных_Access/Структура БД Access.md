БАЗА ДАННЫХ ACCESS (BD.accdb)
==============================

Формат: Microsoft Access 2007+ (.accdb)
Путь: {AppStartupPath}\Data\BD.accdb
Строка подключения: Provider=Microsoft.ACE.OLEDB.12.0;Data Source={путь}

Назначение
----------
Локальное хранилище адресных точек, участков и узлов границ.
Работает автономно от PostgreSQL — служит рабочей базой для балансировки.
Данные могут быть перенесены в PostgreSQL и обратно через панель переноса.

Таблица «Участки»
-----------------
  id         TEXT(50) — первичный ключ (Guid в виде строки)
  Название   TEXT(255)
  Цвет       TEXT(50) — hex-код (#RRGGBB) или строка RGB "R,G,B" (обратная совместимость)
  Долгота    DOUBLE   — долгота центра участка
  Широта     DOUBLE   — широта центра участка

Таблица «Узлы»
--------------
  id           TEXT(50) — первичный ключ
  Долгота      DOUBLE   — долгота вершины полигона
  Широта       DOUBLE   — широта вершины полигона
  Id участка   TEXT(50) — внешний ключ к Участки.id
  Номер        INTEGER  — порядковый номер вершины (задаёт правильный обход полигона)

Таблица «Метки»
---------------
  id           TEXT(50) — первичный ключ
  Долгота      DOUBLE
  Широта       DOUBLE
  Тип здания   TEXT(255)
  Улица        TEXT(255)
  Дом          TEXT(50)
  Корпус       TEXT(50)
  Квартира     TEXT(50)
  Id участка   TEXT(50) — внешний ключ к Участки.id (может быть NULL)
  Участок      INTEGER  — числовой индекс участка (заполняется SaveRegionsToDatabaseOld)

Примечание по координатному своп
---------------------------------
В таблице Узлы столбец «Долгота» хранит широту (lat), а «Широта» — долготу (lon).
Это намеренная особенность, унаследованная в момент создания схемы.
При загрузке из Access в LoadRegionsFromNewTables():
  nodeLng = reader["Долгота"] → передаётся как Lng в PointLatLng
  nodeLat = reader["Широта"]  → передаётся как Lat в PointLatLng
Таким образом данные отображаются корректно, но названия столбцов инвертированы.
При переносе Access → PostgreSQL и PostgreSQL → Access своп воспроизводится
зеркально, чтобы обе стороны хранили данные в одном порядке.

В таблице Метки своп не применяется: Широта = lat, Долгота = lon.

Ограничения Access DDL
-----------------------
PRIMARY KEY inline для TEXT-столбцов через OleDb DDL не поддерживается.
PRIMARY KEY задаётся только в CREATE TABLE в эталонной схеме (в исходном коде),
но при фактическом создании через CreateFreshAccessDatabase() эти ключевые слова
удаляются и первичные ключи не создаются. Уникальность обеспечивается логикой
приложения (INSERT всегда использует новый Guid).

ALTER TABLE в Access не поддерживает изменение типа существующего столбца.
При обнаружении неверного типа TryRepairAccessStructure() возвращает false,
и файл БД пересоздаётся с нуля.
