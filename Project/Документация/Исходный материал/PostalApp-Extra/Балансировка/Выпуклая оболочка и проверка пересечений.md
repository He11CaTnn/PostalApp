ВЫПУКЛАЯ ОБОЛОЧКА И ПРОВЕРКА ПЕРЕСЕЧЕНИЙ
==========================================

Методы: BuildConvexHulls, CalculateConvexHull, CheckPointIntersections,
        RedistributeConflictingPoints, IsPointInPolygon
Класс: CreateBalancedRegions

Назначение
----------
Выпуклая оболочка используется как форма полигона участка. Алгоритм Грэхема строит
минимальный выпуклый многоугольник вокруг точек кластера. Проверка пересечений
гарантирует, что каждая точка принадлежит ровно одному участку.

Алгоритм Грэхема (CalculateConvexHull)
---------------------------------------
Входные данные: список PointLatLng (минимум 3 точки).

1. Стартовая точка: самая нижняя (min Lat), при равенстве — самая левая (min Lng).
2. Остальные точки сортируются по полярному углу относительно стартовой:
   atan2(p.Lat - start.Lat, p.Lng - start.Lng).
3. Обход в порядке сортировки:
   Пока hull.Count >= 2 и CrossProduct(hull[-2], hull[-1], point) <= 0:
     удаляется hull[-1].
   Добавляется текущая точка.

CrossProduct(O, A, B) = (A.Lng - O.Lng)×(B.Lat - O.Lat) - (A.Lat - O.Lat)×(B.Lng - O.Lng)
Отрицательное или нулевое значение означает поворот по часовой стрелке или коллинеарность —
такие точки из оболочки исключаются.

При менее чем 3 точках — возвращается исходный список без обработки.

Итог: region.ConvexHullPoints. После BuildRegionPolygons()
region.PolygonPoints := region.ConvexHullPoints.

Проверка пересечений (CheckPointIntersections)
-----------------------------------------------
Для каждой AddressPoint из allPoints определяется, в скольких регионах
она находится (IsPointInPolygon по ConvexHullPoints, только если точек >= 3).

Если точка в нескольких регионах — она ConflictingPoint.
Если ни в одном — Debug.WriteLine (не считается конфликтом).

IntersectionCheckResult:
  IsValid           — true если ConflictingPoints пуст
  ConflictingPoints — список точек, попавших более чем в один регион
  PointRegions      — Dict<pointId, List<regionIndex>>

IsPointInPolygon (Ray casting algorithm)
-----------------------------------------
Для точки (lat, lng) и полигона:
  Считается количество пересечений луча, идущего вправо от точки, с рёбрами полигона.
  Нечётное количество → точка внутри.
Ребро [i, j] учитывается если (polygon[i].Lat > lat) != (polygon[j].Lat > lat).

Перераспределение конфликтных точек (RedistributeConflictingPoints)
---------------------------------------------------------------------
Фаза 1 — конфликтные точки (в нескольких регионах):
  Для каждой конфликтной точки из всех регионов-кандидатов находится ближайший по центру.
  Точка удаляется из всех регионов и добавляется в ближайший.

Фаза 2 — осиротевшие точки (ни в одном регионе):
  Для каждой такой точки находится регион с ближайшим центром.
  Точка переназначается туда.
