ОПТИМИЗАЦИЯ ГРАНИЦ УЧАСТКОВ
============================

Методы: OptimizeRegionBoundaries(), OptimizeSingleRegionBoundary(),
        OptimizePolygonBoundary(), CountPolygonIntersections(), DoSegmentsIntersect()
Класс: CreateBalancedRegions

Назначение
----------
Порядок вершин полигона влияет на правильность его отрисовки — самопересекающийся
полигон выглядит как «бабочка» вместо корректной формы. Оптимизатор уменьшает
количество самопересечений рёбер путём попарной перестановки соседних вершин.

Определение пересечения отрезков (DoSegmentsIntersect)
-------------------------------------------------------
Проверяет пересечение отрезков [p1,p2] и [p3,p4] через направления:
  d1 = Direction(p3,p4,p1), d2 = Direction(p3,p4,p2)
  d3 = Direction(p1,p2,p3), d4 = Direction(p1,p2,p4)
  Direction(O,A,B) = (A.Lng-O.Lng)×(B.Lat-O.Lat) - (A.Lat-O.Lat)×(B.Lng-O.Lng)
Отрезки пересекаются если d1,d2 имеют разные знаки И d3,d4 имеют разные знаки.

Подсчёт самопересечений (CountPolygonIntersections)
----------------------------------------------------
Для каждого ребра [i, i+1%n] проверяется пересечение с каждым несмежным ребром [j, j+1%n]:
  j > i+1, j не является предыдущим ребром (i+n-1%n).
Возвращает суммарное количество пар пересекающихся рёбер.

Оптимизация полигона (OptimizePolygonBoundary)
-----------------------------------------------
Если CountPolygonIntersections == 0 → возвращает исходный список.
Иначе итерационный swap соседних вершин (максимум 1000 итераций):
  Для i = 0..n-1: j = (i+1) % n.
    Создаётся копия списка, меняются местами elements[i] и elements[j].
    CountPolygonIntersections для новой перестановки.
    Если intersections < bestIntersections → обновляется bestPoints.
    Если bestIntersections == 0 → досрочный выход.
  Если за полный проход улучшений не было: noImprovementCount++.
  При noImprovementCount >= 10 → цикл прерывается.

Оптимизация одного участка (OptimizeSingleRegionBoundary)
----------------------------------------------------------
Читает узлы участка из БД Access (SELECT ... WHERE Id участка = ? ORDER BY Номер).
При менее 3 узлов — завершается без изменений.
OptimizePolygonBoundary(points) → optimizedPoints.
DELETE FROM Узлы WHERE Id участка = ?  — удаляет все старые узлы.
INSERT INTO Узлы ... VALUES (?) — записывает оптимизированные узлы с новыми Guid
и последовательными номерами (1, 2, 3, ...).
Вызывается из: HandleCreateNodeClick, HandleMoveObjectClick (узел), HandleDeleteObjectClick (узел)
при условии checkBox1.Checked (автооптимизация).

Оптимизация всех участков (OptimizeRegionBoundaries)
-----------------------------------------------------
Вызывается button9_Click.
LoadRegionsFromNewTables() — загружает все участки из Access.
DELETE FROM Узлы — полная очистка таблицы.
Для каждого участка (>= 3 узлов):
  OptimizePolygonBoundary(region.PolygonPoints) → optimizedPoints.
  INSERT INTO Узлы ... для каждой точки с новым Guid.
После завершения пользователю показывается сообщение с инструкцией
перезагрузить участки из БД для просмотра результата.

Загрузка участков из БД (LoadRegionsFromNewTables)
---------------------------------------------------
SELECT id, Название, Цвет, Долгота, Широта FROM Участки (все участки).
Для каждого участка: SELECT Долгота, Широта, Номер FROM Узлы WHERE Id участка = ? ORDER BY Номер.
Цвет парсится: "#..." → HexToColor(), "R,G,B" → Color.FromArgb(), ошибка → regionColors[idx].
region.CenterPoint = PointLatLng(Широта, Долгота) из таблицы Участки.
region.PolygonPoints заполняется в порядке Номер: PointLatLng(Широта, Долгота)
— здесь своп: reader["Долгота"] → Lng, reader["Широта"] → Lat.
