РУЧНОЙ ВХОД
===========

Назначение
----------
Вход в систему по email и паролю. Используется когда автовход недоступен:
устройство не зарегистрировано, PermanentAccess = false, или не удалось получить ID материнской платы.

Последовательность
------------------
Метод: StartupForm.HandleLoginClick()

1. Проверка заполненности полей email и пароля. Если хотя бы одно пустое — показывается
   ошибка, запрос не отправляется.

2. Блокировка интерфейса: кнопка, поля ввода, чекбокс переводятся в disabled.
   Кнопка меняет текст на «Подождите...». Отображается прогресс-экран.

3. Вызов SecureConfig.FetchConfigFromServer(email, password):
   - Отправляет POST /api/getconfig с email, паролем, версией и MD5 exe.
   - При успехе возвращает ServerConfig со строкой подключения и координатами.
   - Исключения обрабатываются отдельными catch-блоками (см. Исключения соединения.txt).

4. ApplyConfigToProgram(cfg) записывает параметры PostgreSQL в статические свойства
   Program (ServerIP, ServerPort, ServerDatabase, ServerUser, ServerPassword) и
   устанавливает Map.startPosition из координат конфига.

5. DataBase.TryConnectAsync() создаёт PgClient и выполняет тестовый запрос
   к таблице «тест» для верификации соединения. Если запрос провалился —
   показывается ошибка, интерфейс разблокируется.

6. UserData.VerifyUser(email, password):
   - Запрашивает запись из таблицы Логин по email.
   - Проверяет пароль через PasswordHasher.VerifyPassword() (PBKDF2-SHA256).
   - Загружает запись из таблицы Сотрудники по IdLogin.
   - Загружает регионы (участки) сотрудника из таблицы Участки.
   - Записывает всё в CurrentUser.Employee, CurrentUser.Login, CurrentUser.RegionIds.
   - Возвращает false при несоответствии данных; в этом случае форма показывает
     ошибку и разблокируется.

7. UserData.RegisterOrUpdateDevice() — регистрирует или обновляет запись об устройстве
   в таблице Устройства. PermanentAccess берётся из чекбокса «Запомнить устройство».

8. Step2_CheckUpdates() — проверка обновлений перед открытием основной формы.

Двойная проверка пароля
-----------------------
Пароль проверяется дважды:
  - На сервере: /api/getconfig использует PBKDF2-SHA256 реализацию на Python (hashlib)
    с теми же параметрами (соль 16 байт, 100000 итераций, dklen=32).
  - На клиенте: UserData.VerifyUser() повторно проверяет пароль уже через прямой
    запрос к PostgreSQL через PasswordHasher.VerifyPassword().
Эта двойная проверка гарантирует, что даже если сервер конфигурации скомпрометирован
и вернул чужую конфигурацию БД — вход в систему без корректного пароля невозможен.

Обработка Enter
---------------
Enter в поле email — переход к полю пароля.
Enter в поле пароля — симулирует нажатие кнопки «Войти».
