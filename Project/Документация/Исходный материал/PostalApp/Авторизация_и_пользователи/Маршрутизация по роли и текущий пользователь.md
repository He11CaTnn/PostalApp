МАРШРУТИЗАЦИЯ ПО РОЛИ И ТЕКУЩИЙ ПОЛЬЗОВАТЕЛЬ
=============================================

Текущий пользователь (CurrentUser)
------------------------------------
Вложенный статический класс: UserData.CurrentUser

Свойства:
  Employee   — объект DataBase.Employees (ФИО, роль, IdLogin, дата создания)
  Login      — объект DataBase.Login (email, хэш пароля)
  RegionIds  — List<Guid> идентификаторов участков, назначенных сотруднику

Метод Clear() обнуляет все три свойства и очищает список RegionIds.
Вызывается при выходе из аккаунта (LogoutAndExit).

Данные в CurrentUser записываются:
  - VerifyUser() — при ручном входе
  - LoadUserByMotherboardId() — при автовходе

RegionIds используется картой для фильтрации маркеров и регионов:
директор видит всё, остальные роли — только свои регионы.

Маршрутизация по роли
----------------------
Метод: UserData.OpenRoleForm(employee, callerForm)

На основании employee.Role (регистронезависимое сравнение) открывается одна из форм:
  "почтальон"              → postmanForm
  "оператор"               → operatorForm
  "руководитель подписок"  → managerForm
  "директор"               → directorForm

Алгоритм:
1. Создаётся экземпляр формы.
2. Форма показывается через Show().
3. callerForm скрывается через Hide() (не закрывается, что позволяет вернуться к ней при выходе).
4. Действие логируется через Logger.Info.

Если роль неизвестна — Logger.ShowWarning показывает сообщение пользователю.

Выход из аккаунта
-----------------
Метод: UserData.LogoutAndExit(currentForm)

1. CurrentUser.Clear() сбрасывает данные текущего пользователя.
2. Создаётся новый экземпляр StartupForm и показывается.
3. Текущая форма закрывается через Close().
StartupForm при повторном показе снова запускает RunStartupSequence() —
автовход сработает снова если устройство зарегистрировано с PermanentAccess = true.

Регистрация нового сотрудника
------------------------------
Метод: UserData.Register(email, password, fio, role, dataGridView, locallyAddedEmployeesIds)

1. Проверяет заполненность всех полей.
2. Проверяет уникальность email в таблице Логин.
3. Хэширует пароль через PasswordHasher.HashPassword() (PBKDF2-SHA256).
4. Создаёт запись в таблице Логин (INSERT, получает сгенерированный Id).
5. Создаёт запись в таблице Сотрудники с новым Guid, ссылкой на IdLogin,
   датой создания DateTime.UtcNow.
6. При ошибке на шаге 5 — откатывает вставку логина (DELETE по Id).
7. Если передан dataGridView — добавляет строку через DataTables.AddEmployeeRow()
   и регистрирует Id в locallyAddedEmployeesIds.
