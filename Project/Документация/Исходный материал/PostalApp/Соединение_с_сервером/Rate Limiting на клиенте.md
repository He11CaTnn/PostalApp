RATE LIMITING — КЛИЕНТСКАЯ СТОРОНА
===================================

Назначение
----------
При получении HTTP 429 от сервера клиент не просто показывает сообщение об ошибке,
а блокирует интерфейс на точное количество секунд, указанное сервером в ответе.

Как сервер передаёт время блокировки
--------------------------------------
Тело ответа HTTP 429 содержит JSON:
  {"detail":{"reason":"rate_limit","retry_after":N}}
где N — количество секунд до сброса ограничения.

Метод ParseRetryAfter() в SecureConfig извлекает значение N регулярным выражением
\"retry_after\"\s*:\s*(\d+) и передаёт его в конструктор RateLimitException.

Обработка в StartupForm
-----------------------
Метод: StartRateLimitCountdown(int retryAfterSeconds)

1. Останавливается предыдущий таймер, если он уже был запущен (StopRateLimitTimer()).
2. Запоминается значение retryAfterSeconds в поле _rateLimitSecondsLeft.
3. Блокируются: кнопка «Войти», поля email и пароля, чекбокс «Запомнить устройство».
4. Запускается System.Windows.Forms.Timer с интервалом 1000 мс.
5. При каждом тике: декрементируется _rateLimitSecondsLeft, обновляется метка с
   оставшимся временем («Слишком много попыток. Попробуйте через N сек.»).
6. Когда счётчик достигает нуля:
   - Таймер останавливается и уничтожается.
   - Сообщение об ошибке очищается.
   - Интерфейс разблокируется.
   - Фокус устанавливается на поле email.

Где срабатывает
---------------
- При ручном входе через кнопку «Войти» (HandleLoginClick).
- При автовходе по ID материнской платы (HandleDeviceAutoLogin).
  В случае автовхода это означает, что IP заблокирован из-за превышения лимита
  именно ручного входа (сервер проверяет лимит ручного входа перед лимитом автовхода).

Таймер при закрытии формы
--------------------------
При нажатии кнопки закрытия окна (BtnClose_Click) вызывается StopRateLimitTimer()
перед Program.AppExit() — это предотвращает попытку обращения к уничтоженному
элементу управления из тика таймера.
