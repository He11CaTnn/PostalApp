SSL PINNING
===========

Что это
-------
SSL Pinning — механизм, при котором клиент не просто проверяет сертификат сервера через цепочку
доверенных центров сертификации, а сравнивает его с заранее вшитым в код эталонным значением.
Это исключает возможность MitM-атаки (man-in-the-middle) через подставной CA-сертификат.

Где используется
----------------
Класс: SecureConfig
Метод: CreateSslHandler()

Применяется при каждом HTTP-запросе к конфигурационному серверу:
  - POST /api/getconfig     (ручной вход)
  - POST /api/checkdevice   (автовход по материнской плате)

Оба запроса создают HttpClient с хэндлером, возвращённым из CreateSslHandler(),
поэтому pinning активен на каждом из них.

Как работает
------------
1. В классе SecureConfig объявлена константа ExpectedCertFingerprint — SHA-256 хэш
   DER-байт сертификата сервера в uppercase hex без разделителей.

2. При создании HttpClientHandler устанавливается делегат
   ServerCertificateCustomValidationCallback. Этот делегат вызывается TLS-стеком .NET
   после получения сертификата от сервера — до того, как соединение считается установленным.

3. Внутри делегата вызывается GetCertFingerprint(cert.RawData):
   - cert.RawData — сырые DER-байты сертификата, предоставленные TLS-стеком.
   - SHA256.ComputeHash применяется к этим байтам.
   - Результат конвертируется в uppercase hex-строку без дефисов.

4. Полученный fingerprint сравнивается с ExpectedCertFingerprint через
   string.Equals(..., OrdinalIgnoreCase).
   Если значения совпадают — делегат возвращает true, соединение устанавливается.
   Если не совпадают — возвращается false, HttpClient бросает HttpRequestException,
   а в лог записывается фактический fingerprint.

Что проверяется
---------------
Проверяется SHA-256 хэш от сырых DER-байт сертификата (RawData), а не от его
публичного ключа. Это означает: при перевыпуске сертификата (даже с тем же ключом)
fingerprint изменится и приложение откажется соединяться до обновления константы
ExpectedCertFingerprint в коде.

Последствия при несоответствии
-------------------------------
- Делегат возвращает false.
- Logger.Error записывает реальный fingerprint в лог (для диагностики).
- HttpClient не устанавливает соединение, бросает HttpRequestException.
- В StartupForm эта исключение ловится как общий Exception в блоке catch,
  после чего форма показывает сообщение об ошибке подключения к серверу.
