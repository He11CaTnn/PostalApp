СИСТЕМА РОЛЕЙ
==============

Файлы: js/app.js, js/admin.js, js/config.js, firestore.rules

Четыре роли
-----------
Роли определяются комбинацией полей в Firestore и email-адреса.

1. Главный администратор (Super Admin)
   Определяется исключительно по email из SITE_CONFIG.superAdminEmail.
   Проверка: isSuperAdmin(user) → user.email === SITE_CONFIG.superAdminEmail
   Никакие поля в Firestore не нужны.
   Привилегии:
     - Полный доступ к панели администратора.
     - Может назначать других пользователей администраторами.
     - Не может быть разжалован через UI.
     - Единственная роль, фиксированная в конфигурации.

2. Администратор (Admin)
   Поле Firestore: isAdmin == true (и опционально isModerator == true).
   Проверка: isAdminRole(user, userData) → isSuperAdmin(user) || userData?.isAdmin === true
   Привилегии:
     - Доступ к /admin.html (панели управления).
     - Одобрение/отклонение заявок.
     - Изменение роли до «Модератор» и обратно.
     - Доступ к скачиванию дополнительного приложения.
   Ограничения:
     - Не может назначать других администраторов.
     - Не может разжаловать других администраторов.
     - Не может изменить свою собственную роль.
   Назначается: суперадмином через кнопку «👑 Администратором» в панели заявок
                или через select роли в таблице пользователей.

3. Модератор (Moderator)
   Поле Firestore: isModerator == true, isAdmin == false.
   Проверка: isModeratorRole(userData) → userData?.isModerator === true
   Привилегии:
     - Доступ к скачиванию PostalApp Extra.
     - Отображение метки «Модератор» в личном кабинете.
   Назначается: администратором через кнопку «✅ Модератором» в панели заявок
                или через select роли в таблице пользователей.

4. Пользователь (User)
   isAdmin == false, isModerator == false (или поля отсутствуют).
   Права:
     - Вход через Google.
     - Просмотр информации о приложении.
     - Скачивание основного приложения (PostalApp).
     - Подача заявки на доступ к Extra.
   Без роли — не видит кнопку скачивания Extra.

Защита от привилегий
---------------------
Двойная защита для ролей:

На уровне клиентского JS:
  - setRole() проверяет isSuperAdminSession перед назначением admin.
  - setRole() запрещает изменение своей роли (adminUser.uid === uid).
  - approveAsAdmin() проверяет isSuperAdminSession.

На уровне Firestore Rules:
  - Пользователь не может обновить isModerator или isAdmin в своём документе.
  - Назначение ролей доступно только через isAdmin() → вызов от администратора.

Отображение в UI
----------------
Навбар: ссылка «Панель» появляется только при isAdminRole().
Личный кабинет: badge и статус-блок с текстом, соответствующим роли.
Карточка Extra: кнопка скачивания — только при isAdminRole() или isModeratorRole().
Форма заявки: показывается только пользователям без роли и без активной заявки.
